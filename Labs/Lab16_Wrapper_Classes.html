05 Comparing wrapper objects — The == trap Comparison

Create a class named WrapperComparison.

This exercise exposes a common bug. Inside main:

Part 1 — Integer caching (values -128 to 127):

  • Integer a = 100; Integer b = 100;
  • Print a == b → true (Java caches small integers, same object)
  • Integer c = 200; Integer d = 200;
  • Print c == d → false (outside cache range, different objects!)

Part 2 — Safe comparison with .equals():

  • Print a.equals(b) → true
  • Print c.equals(d) → true

Part 3 — compareTo():

  • Integer x = 10; Integer y = 20; Integer z = 10;
  • Print x.compareTo(y) → negative (x < y)
  • Print y.compareTo(x) → positive (y > x)
  • Print x.compareTo(z) → 0 (equal)
--- Integer caching trap --- a = 100, b = 100 a == b: true (cached — same object) c = 200, d = 200 c == d: false (NOT cached — different objects!) --- Safe comparison with .equals() --- a.equals(b): true c.equals(d): true --- compareTo() --- 10.compareTo(20): -1 (less than) 20.compareTo(10): 1 (greater than) 10.compareTo(10): 0 (equal)
Critical rule: NEVER use == to compare wrapper objects. It compares object references, not values. Always use .equals() for value comparison. The caching behavior of small integers makes == appear to work sometimes, making the bug hard to find.

07 Null safety — The NullPointerException trap null

Create a class named NullSafety.

Inside main, demonstrate the danger of null with wrapper classes:

  1. Declare Integer num = null;
  2. Try to unbox it: int value = num; — this causes NullPointerException during unboxing. Catch it and print the error.
  3. Show the safe way: check for null before unboxing.
    • if (num != null) { int value = num; }
  4. Demonstrate with Boolean: Boolean flag = null; if (flag) { ... } — also causes NPE. Catch it.
  5. Write a safe helper method: public static int safeUnbox(Integer value, int defaultValue) — returns the int if not null, otherwise returns the default.
--- Null unboxing trap --- Integer num = null Attempting int value = num... NullPointerException! Cannot unbox null to int. --- Null boolean trap --- Boolean flag = null Attempting if (flag)... NullPointerException! Cannot unbox null to boolean. --- Safe unboxing --- safeUnbox(42, 0) = 42 safeUnbox(null, 0) = 0 safeUnbox(null, -1) = -1
Critical rule: Wrapper objects can be null — primitives cannot. When Java tries to unbox a null wrapper, it crashes with NullPointerException. Always check for null before unboxing.

Key learning: Collections like ArrayList and HashMap cannot store primitives — only objects. This is why wrapper classes exist. Autoboxing makes this seamless: you write list.add(42) and Java converts it to list.add(Integer.valueOf(42)) automatically.
