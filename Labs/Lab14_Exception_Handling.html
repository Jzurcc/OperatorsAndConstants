Quick reference
Keyword Purpose
try Wraps code that might throw an exception.
catch Handles a specific exception type. You can have multiple catch blocks.
finally Runs always — whether an exception occurred or not. Used for cleanup.
throw Manually throws an exception: throw new IllegalArgumentException("msg");
throws Declares that a method might throw a checked exception: public void read() throws IOException
Checked exceptions Unchecked exceptions
When? Checked at compile time Occur at runtime
Must handle? Yes — try-catch or throws No — but you should
Extends Exception RuntimeException
Examples IOException, FileNotFoundException NullPointerException, ArithmeticException, ArrayIndexOutOfBoundsException

Exercises
01 Basic try-catch try-catch

Create a class named BasicTryCatch.

Inside main, write three separate try-catch blocks that intentionally cause and catch these exceptions:

  1. ArithmeticException: divide an int by zero.
  2. ArrayIndexOutOfBoundsException: access index 10 of a 5-element array.
  3. NumberFormatException: parse the string "abc" using Integer.parseInt().

In each catch block, print the exception type and its message. After all three blocks, print "Program continues normally."

--- Test 1: Division by zero --- Caught: ArithmeticException — / by zero --- Test 2: Array index out of bounds --- Caught: ArrayIndexOutOfBoundsException — Index 10 out of bounds for length 5 --- Test 3: Number format --- Caught: NumberFormatException — For input string: "abc" Program continues normally.
Key learning: Without try-catch, any of these exceptions would crash the program. With it, the exception is caught, the error is handled, and the program keeps running.
02 Multiple catch blocks try-catch Multiple catch

Create a class named MultipleCatch.

Inside main, declare:

  • String[] values = {"10", "abc", "30", null, "50"};

Write a single try block with multiple catch blocks that loops through the array and attempts to parse each string to an int and divide 100 by it. Handle these in order:

  1. NumberFormatException — for non-numeric strings
  2. NullPointerException — for null values
  3. ArithmeticException — in case any parsed value is 0
  4. Exception — catch-all for anything unexpected (put this last)

Print which index caused which exception.

Index 0: 100 / 10 = 10 Index 1: NumberFormatException — For input string: "abc" Index 2: 100 / 30 = 3 Index 3: NullPointerException — Cannot parse null Index 4: 100 / 50 = 2
Key learning: When using multiple catch blocks, order matters — put the most specific exception first, and the most general (Exception) last. Java checks them top to bottom and runs the first matching catch.
03 The finally block finally

Create a class named FinallyBlock.

Inside main, demonstrate three scenarios using try-catch-finally:

  1. No exception: Divide 10 by 2. The finally block prints "Finally block executed."
  2. Exception caught: Divide 10 by 0. Catch the exception. The finally block still runs.
  3. Simulating resource cleanup: Print "Opening connection..." in try, cause an exception, and in finally print "Closing connection... (cleanup)"
--- Scenario 1: No exception --- Result: 5 Finally block executed. --- Scenario 2: Exception caught --- Caught: ArithmeticException — / by zero Finally block executed. --- Scenario 3: Resource cleanup --- Opening connection... Caught: Something went wrong! Closing connection... (cleanup)
Key learning: finally always runs — whether the try succeeds, fails, or even has a return statement. It's the right place for cleanup: closing files, database connections, network sockets, etc.
04 The throw keyword throw

Create a class named ThrowKeyword.

Write the following static methods that validate input and throw exceptions manually:

  • public static void validateAge(int age) — if age < 0 or age > 150, throw new IllegalArgumentException("Invalid age: " + age)
  • public static void validateName(String name) — if name is null or empty, throw new IllegalArgumentException("Name cannot be null or empty.")
  • public static double divide(int a, int b) — if b is 0, throw new ArithmeticException("Cannot divide by zero.")

Inside main, call each method with valid and invalid inputs. Wrap each call in try-catch.

--- validateAge --- Age 25: Valid Age -5: Caught — Invalid age: -5 Age 200: Caught — Invalid age: 200 --- validateName --- Name "Alice": Valid Name "": Caught — Name cannot be null or empty. Name null: Caught — Name cannot be null or empty. --- divide --- 10 / 3 = 3.33 10 / 0: Caught — Cannot divide by zero.
Key learning: throw lets you create and throw your own exceptions. Use it in validation methods to reject bad data early instead of letting errors silently propagate.
05 The throws keyword throws

Create a class named ThrowsKeyword.

Write the following methods that declare exceptions using throws:

  • public static int parseAge(String input) throws NumberFormatException — parses the string to int. If parsing fails, the exception propagates to the caller.
  • public static void checkEligibility(int age) throws Exception — throws new Exception("Must be 18 or older.") if age < 18.
  • public static void processApplication(String ageInput) throws Exception — calls parseAge() then checkEligibility(). Exceptions propagate up.

Inside main, call processApplication() with different inputs. Handle exceptions in main.

--- Application 1: "25" --- Age: 25 Application accepted! --- Application 2: "15" --- Rejected: Must be 18 or older. --- Application 3: "abc" --- Error: Invalid age input — For input string: "abc"
Key learning: throws in the method signature tells the caller: "This method might throw this exception — you deal with it." The actual handling happens in the method that calls it. This is called exception propagation.
06 Checked vs unchecked exceptions Checked try-catch

Create a class named CheckedVsUnchecked.

Demonstrate both types:

Part 1 — Unchecked (RuntimeException):

  1. Cause a NullPointerException: call .length() on a null String.
  2. Cause a StringIndexOutOfBoundsException: call .charAt(50) on a short String.
  3. Cause a ClassCastException: cast an Object (that's a String) to Integer.

Wrap each in try-catch. These compile without try-catch, but crash at runtime.

Part 2 — Checked (Exception):

  1. Write a method: public static void riskyOperation() throws Exception — throws new Exception("Simulated checked exception").
  2. Call it from main. You must either catch it or declare throws — the code won't compile otherwise. Use try-catch.
--- Unchecked exceptions (runtime) --- NullPointerException: Cannot invoke "String.length()" because "str" is null StringIndexOutOfBoundsException: String index out of range: 50 ClassCastException: java.lang.String cannot be cast to java.lang.Integer --- Checked exception (compile-time) --- Caught checked exception: Simulated checked exception (This would NOT compile without try-catch or throws!)

Create TestCustomException. Write a static method:

  • public static void registerVoter(String name, int age) throws InvalidAgeException — if age < 18 or > 120, throw new InvalidAgeException(age, "Age " + age + " is not valid for voter registration.")

In main, test with valid and invalid ages.

Key learning: Custom exceptions let you create meaningful, domain-specific error types. Instead of a generic Exception, InvalidAgeException tells the caller exactly what went wrong and carries extra data (the age).

10 Putting it all together — Order processing system Mixed

This capstone combines try-catch-finally, throw, throws, multiple catch blocks, and custom exceptions.

Create the following custom exceptions (each in its own file, all extending Exception). You may create them as inner classes in one file or separate files — your choice:

  • OutOfStockException — fields: String product;, int requested;, int available;
  • InvalidQuantityException — field: int quantity;
  • PaymentFailedException — field: String reason;

Create a class OrderProcessor with:

  • static String[] products = {"Laptop", "Mouse", "Keyboard"};
  • static int[] stock = {5, 20, 15};
  • static double[] prices = {45999.0, 599.0, 1299.0};

Add static methods:

  • public static void validateQuantity(int qty) throws InvalidQuantityException — throws if qty ≤ 0
  • public static int findProduct(String name) throws IllegalArgumentException — returns index, throws if product not found
  • public static void checkStock(int index, int qty) throws OutOfStockException — throws if qty > stock
  • public static void processPayment(double amount, boolean hasEnoughFunds) throws PaymentFailedException — throws if insufficient funds
  • public static void placeOrder(String product, int qty, boolean hasEnoughFunds) — calls all above methods in a try block, catches each exception type, and has a finally block printing "Order processing complete."

Create a test class. Place several valid and invalid orders.

======================================== ORDER PROCESSING SYSTEM ======================================== --- Order 1: Laptop x 2 --- Validating quantity... OK Finding product... Found at index 0 Checking stock... 5 available, 2 requested — OK Processing payment of 91998.0... OK Order placed! Remaining stock: 3 [finally] Order processing complete. --- Order 2: Mouse x 0 --- InvalidQuantityException: Quantity must be greater than 0. Got: 0 [finally] Order processing complete. --- Order 3: Monitor x 1 --- Product not found: Monitor [finally] Order processing complete. --- Order 4: Keyboard x 20 --- OutOfStockException: Not enough Keyboard in stock. Requested: 20, Available: 15 [finally] Order processing complete. --- Order 5: Mouse x 5 (insufficient funds) --- PaymentFailedException: Insufficient funds. [finally] Order processing complete. ========================================
Key takeaway: This exercise mirrors a real-world workflow: each step can fail differently, each failure is a specific exception with meaningful data, and every path — success or failure — goes through finally for cleanup. This is how exception handling works in production Java applications.
