Access Modifiers

This exercise will test your understanding of Java's four access modifiers: public, private, protected, and default (no keyword). You will create classes across multiple packages to observe how each modifier controls visibility. Follow every instruction carefully.

Project setup

Follow these steps exactly:

  1. Open IntelliJ IDEA.
  2. Create a new Java project named AccessModifiers.
  3. Inside the src folder, create three packages:
    com.school.access — main package for most classes
    com.school.access.sub — for subclass exercises
    com.school.other — a separate package to test cross-package access
  4. For each exercise below, create the class files specified in the correct package.
  5. Each test/main class must have a public static void main(String[] args) method.
Important: This lab requires multiple packages and multiple classes per exercise. Pay close attention to which package each class belongs to.

Exercises
01 Public — Accessible everywhere public

In package com.school.access, create a class named Person.

Declare the following public fields and a public method:

  • public String name = "Maria Santos";
  • public int age = 25;
  • public String greet() — returns "Hello, my name is " + name

In the same package, create TestSameClass with a main method. Create a Person object and print all fields and the greet message.

Name: Maria Santos Age: 25 Hello, my name is Maria Santos
02 Public — Access from a different package public

In package com.school.other, create a class named TestFromOutside.

Import com.school.access.Person and create a Person object inside main. Access and print the same fields and method as Exercise 01.

This should compile and run successfully because all members are public.

--- Accessing Person from a different package --- Name: Maria Santos Age: 25 Hello, my name is Maria Santos
03 Private — Accessible only within the same class private

In package com.school.access, create a class named BankAccount.

Declare:

  • private String accountNumber = "1234-5678-9012";
  • private double balance = 50000.00;
  • public String getAccountNumber() — returns accountNumber
  • public double getBalance() — returns balance
  • public void deposit(double amount) — adds amount to balance and prints a confirmation

In the same package, create TestBankAccount with a main method. Create a BankAccount object, call the public methods, and print the results.

Key learning: You cannot access accountNumber or balance directly (e.g. account.balance will cause a compile error). You must use the public getter methods. Try accessing them directly first to see the error, then comment out those lines and use the getters instead.
Account: 1234-5678-9012 Balance: 50000.0 Depositing 10000.0... New balance: 60000.0
04 Private — Proving it fails from another package private

In package com.school.other, create a class named TestBankFromOutside.

Import com.school.access.BankAccount and create an object in main.

Step 1: Try to access account.balance directly. You will get a compile error. Take a screenshot of the error or write the error message as a comment in your code.

Step 2: Comment out the direct access line. Use the public getter methods instead so the class compiles.

// account.balance → ERROR: balance has private access in BankAccount

Your final working code should print:

--- Accessing BankAccount from a different package --- Account (via getter): 1234-5678-9012 Balance (via getter): 50000.0
05 Default (package-private) — Same package only default

In package com.school.access, create a class named Product.

Declare the following fields with no access modifier (default/package-private):

  • String productName = "Laptop";
  • double price = 45999.00;
  • int stock = 15;

Also declare a default method (no modifier):

  • String getInfo() — returns a formatted string with all product details

In the same package, create TestProduct with a main method. Create a Product object and access all fields and the method directly.

Product: Laptop Price: 45999.0 Stock: 15 Info: Laptop - 45999.0 (15 in stock)

This works because both classes are in the same package.

06 Default — Proving it fails from another package default

In package com.school.access.sub, create a class named TestDifferentPackage.

Import com.school.access.Product and create a Product object in main.

Step 1: Try to access product.productName, product.price, and product.getInfo(). All will cause compile errors because default members are not visible outside their package.

Step 2: Write each error as a comment in your code. Then comment out the failing lines so the class compiles.

// product.productName → ERROR: productName is not public; cannot be accessed from outside package // product.getInfo() → ERROR: getInfo() is not public; cannot be accessed from outside package

Your final code should compile with the direct access lines commented out and a message explaining why:

--- Testing default access from a different package --- Cannot access default members from outside the package. Default (package-private) members are only visible within com.school.access.
07 Protected — Accessible in subclasses protected

In package com.school.access, create a class named Animal.

Declare:

  • protected String species = "Unknown";
  • protected int legs = 4;
  • protected String describe() — returns species + " has " + legs + " legs"

In package com.school.access.sub, create a class named Dog that extends Animal.

  • In the constructor (or directly), set species = "Dog"; and legs = 4;
  • Add a public method bark() that returns "Woof! I am a " + species

In package com.school.access.sub, create TestDog with a main method. Create a Dog object and call both the inherited describe() method and the bark() method.

Description: Dog has 4 legs Bark: Woof! I am a Dog
Key learning: Even though Animal is in a different package, the Dog subclass can access protected members because protected allows access in subclasses regardless of package.
08 Protected — Non-subclass from different package cannot access protected

This exercise proves that protected does NOT grant access to non-subclass code in a different package.

In package com.school.other, open or update TestFromOutside (or add a new section in main).

Step 1: Create an Animal object and try to access animal.species and animal.describe(). These will cause compile errors.

Step 2: Write the errors as comments, then comment out the failing lines.

// animal.species → ERROR: species has protected access in Animal // animal.describe() → ERROR: describe() has protected access in Animal

Your final code should print:

--- Testing protected access from non-subclass in different package --- Cannot access protected members from a non-subclass in a different package.
09 All four modifiers in one class All modifiers

In package com.school.access, create a class named Employee.

Declare one field for each access level:

  • public String name = "Juan Dela Cruz";
  • protected String department = "Engineering";
  • String position = "Developer"; (default — no modifier)
  • private double salary = 75000.00;

Add a public method:

  • public void displayInfo() — prints all four fields (this works because the method is inside the same class, so even private fields are accessible)

Inside the same class, add a main method. Create an Employee object and call displayInfo().

=== Employee Info === [public] Name: Juan Dela Cruz [protected] Department: Engineering [default] Position: Developer [private] Salary: 75000.0
Key learning: Inside the same class, all four access levels are accessible. The restrictions only apply when accessing from outside the class.
10 Putting it all together — Access test from another package All modifiers

In package com.school.other, create a class named TestEmployee.

Import com.school.access.Employee and create an Employee object in main.

Try to access each field one by one. For each one, write a comment documenting whether it is accessible or not, and why:

  1. emp.name — public: should work
  2. emp.department — protected: should fail (not a subclass)
  3. emp.position — default: should fail (different package)
  4. emp.salary — private: should fail
  5. emp.displayInfo() — public: should work

Comment out lines that don't compile, and add the error as a comment. Your final output:

=== Access Modifier Test from com.school.other === [public] emp.name: Juan Dela Cruz --> ACCESSIBLE [protected] emp.department --> NOT ACCESSIBLE (not a subclass, different package) [default] emp.position --> NOT ACCESSIBLE (different package) [private] emp.salary --> NOT ACCESSIBLE (private to Employee class only) [public] emp.displayInfo(): === Employee Info === [public] Name: Juan Dela Cruz [protected] Department: Engineering [default] Position: Developer [private] Salary: 75000.0
Key takeaway: From a different package (non-subclass), only public members are accessible. The displayInfo() method can print all fields because it runs inside the Employee class.
