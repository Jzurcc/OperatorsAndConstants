super & final Keywords

This exercise covers two important Java keywords: super (to access parent class members and constructors) and final (to create constants, prevent method overriding, and prevent class inheritance). Follow every instruction carefully.

Quick reference
Keyword Used on Effect
super() Constructor call Calls the parent class constructor. Must be the first statement.
super.field Field access Accesses the parent's field when it is hidden by a child field of the same name.
super.method() Method call Calls the parent's version of an overridden method.
final Variable Value cannot be changed once assigned (constant).
final Method Method cannot be overridden by subclasses.
final Class Class cannot be extended (no subclasses allowed).

01 super() — Calling parent constructor super

Create a class named Animal with:

  • Fields: String name; and int age;
  • A constructor: public Animal(String name, int age) that assigns both and prints "Animal constructor called"
  • A method: public void displayInfo()

Create a class named Dog that extends Animal with:

  • Field: String breed;
  • A constructor: public Dog(String name, int age, String breed) that calls super(name, age) as the first line, then assigns breed and prints "Dog constructor called"
  • A method: public void displayDogInfo() — prints all three fields

Create TestSuperConstructor. Create a Dog object and call both display methods.

Animal constructor called Dog constructor called Name: Bantay Age: 3 Breed: Aspin
Key learning: super(name, age) calls the parent's constructor, passing values up. It must be the first statement in the child constructor. The parent constructor runs first, then the child continues.

03 super.field — Accessing hidden parent field super

Create a class named Vehicle with:

  • Field: String type = "Generic Vehicle";
  • A method: public void showType() — prints the type

Create a class named Car that extends Vehicle with:

  • Field: String type = "Car"; (same name — this hides the parent field)
  • A method: public void showBothTypes() — prints this.type (child) and super.type (parent)

Create TestSuperField. Create a Car object and call showBothTypes().

Child type (this.type): Car Parent type (super.type): Generic Vehicle
Key learning: When a child class declares a field with the same name as the parent, it hides (not overrides) the parent's field. Use super.type to access the parent's version.

05 final method — Cannot be overridden final method

Create a class named Shape with:

  • Field: String color;
  • A constructor that accepts color.
  • A final method: public final String getColor() — returns the color. This cannot be overridden.
  • A regular method: public double getArea() — returns 0.0 (meant to be overridden)

Create a class named Circle that extends Shape with:

  • Field: double radius;
  • A constructor that calls super(color) and sets radius.
  • Override getArea() — return Math.PI * radius * radius
  • Try to override getColor() — you will get a compile error. Write the error as a comment and leave it commented out.

Create TestFinalMethod. Create a Circle and print its color and area.

Color: Red Area: 78.54
// Cannot override getColor() → ERROR: getColor() in Circle cannot override getColor() in Shape; overridden method is final
Key learning: Marking a method as final guarantees it behaves the same way in every subclass. Use it to protect critical logic from being changed.

  • static final int DB_PORT = 3306;
  • static final String DB_NAME = "school_db";
  • A static method: public static String getConnectionString() — returns "jdbc:mysql://localhost:3306/school_db"

Create TestFinalClass. In main:

  1. Print all config values and the connection string.
  2. Try to create a class that extends Config. You will get a compile error. Write the error as a comment.
DB Host: localhost DB Port: 3306 DB Name: school_db Connection: jdbc:mysql://localhost:3306/school_db
// class MyConfig extends Config → ERROR: cannot inherit from final Config
Key learning: A final class cannot have subclasses. Java's String class is a real-world example — nobody can extend it. Use final class for utility or configuration classes that should never be modified through inheritance.

10 Putting it all together — School system Mixed

This exercise combines super, final, constructors, method overriding, and inheritance.

Create a class named SchoolMember with:

  • final int id; — assigned once in constructor
  • String name;
  • int age;
  • static int nextId = 1000;
  • A constructor that auto-generates id (increment nextId), accepts name and age.
  • public final int getId() — cannot be overridden
  • public void displayInfo() — prints id, name, age

Create a class named Teacher that extends SchoolMember with:

  • String subject;
  • final String role = "Teacher"; — constant, always "Teacher"
  • A constructor that calls super(name, age) and sets subject.
  • Override displayInfo(): call super.displayInfo(), then print role and subject

Create a class named Student that extends SchoolMember with:

  • String course;
  • double gpa;
  • final String role = "Student";
  • A constructor that calls super(name, age) and sets course and gpa.
  • Override displayInfo(): call super.displayInfo(), then print role, course, and gpa

Create TestSchoolSystem. Create 2 Teachers and 3 Students. Store them in a SchoolMember[] array and loop through to call displayInfo() on each.

======================================== SCHOOL MEMBER DIRECTORY ======================================== [ID: 1001] Maria Santos, Age: 35 Role: Teacher Subject: Java Programming [ID: 1002] Carlos Garcia, Age: 40 Role: Teacher Subject: Data Structures [ID: 1003] Alice Reyes, Age: 20 Role: Student Course: BSIT GPA: 3.8 [ID: 1004] Bob Cruz, Age: 21 Role: Student Course: BSCS GPA: 3.2 [ID: 1005] Charlie Tan, Age: 19 Role: Student Course: BSIT GPA: 2.9 ======================================== Total members: 5 ========================================
Key takeaway: This exercise demonstrates how super() passes data to the parent constructor, super.displayInfo() reuses parent logic, final int id protects the ID from modification, final getId() prevents subclasses from tampering with ID retrieval, and polymorphism lets you store different types in one array and call the correct overridden method on each.
