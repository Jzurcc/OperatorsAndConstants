Types of inheritance in Java
Type Structure Supported? Example
Single One parent → one child ✓ Yes Animal → Dog
Multilevel Grandparent → parent → child (chain) ✓ Yes Vehicle → Car → ElectricCar
Hierarchical One parent → multiple children (branching) ✓ Yes Shape → Circle, Rectangle, Triangle
Multiple One child extends two or more parents ✗ Not with classes Use interfaces instead
Why Java does NOT support multiple inheritance with classes:
If class C extends both A and B, and both A and B have a method called display(), Java would not know which version to use — this is called the Diamond Problem.

class C extends A, B { } → This will NOT compile.

Java's solution: use interfaces. A class can implement multiple interfaces because the class itself provides the method body, avoiding ambiguity.
class C implements InterfaceA, InterfaceB { } → This works!

Exercises
01 Single inheritance — Animal hierarchy Single

Create a parent class named Animal with:

  • Fields: String name; and int age;
  • A constructor that accepts both.
  • A method: public void eat() — prints "[name] is eating."
  • A method: public void sleep() — prints "[name] is sleeping."
  • A method: public void displayInfo() — prints name and age

Create Dog that extends Animal with:

  • Field: String breed;
  • A constructor that calls super(name, age) and sets breed.
  • A new method: public void bark() — prints "[name] says: Woof!"

Create Cat that extends Animal with:

  • Field: boolean isIndoor;
  • A constructor that calls super(name, age) and sets isIndoor.
  • A new method: public void purr() — prints "[name] is purring."

Create TestAnimal. Create a Dog and a Cat. Call inherited methods (eat, sleep) and child-specific methods.

--- Dog --- Name: Bantay, Age: 3, Breed: Aspin Bantay is eating. Bantay is sleeping. Bantay says: Woof! --- Cat --- Name: Mingming, Age: 2, Indoor: true Mingming is eating. Mingming is sleeping. Mingming is purring.
Key learning: Dog and Cat inherit eat(), sleep(), and displayInfo() from Animal without rewriting them. They only add their own unique behavior.

04 Multilevel inheritance — Vehicle chain Multilevel super

Create a three-level inheritance chain:

Level 1: Vehicle

  • Fields: String brand; and int year;
  • A constructor, and a displayInfo() method.

Level 2: Car extends Vehicle

  • Fields: int doors; and String fuelType;
  • A constructor that calls super(brand, year).
  • @Override displayInfo() — call super.displayInfo(), then print car-specific fields.

Level 3: ElectricCar extends Car

  • Fields: int batteryCapacity; (kWh) and int range; (km)
  • A constructor that calls super(brand, year, doors, "Electric").
  • @Override displayInfo() — call super.displayInfo(), then print battery and range.

Create TestVehicle. Create one of each type.

--- Vehicle --- Brand: Generic Motors Year: 2020 --- Car --- Brand: Toyota Year: 2023 Doors: 4 Fuel: Gasoline --- Electric Car --- Brand: Tesla Year: 2024 Doors: 4 Fuel: Electric Battery: 75 kWh Range: 450 km
Key learning: Each level adds its own data and calls super to reuse the parent's logic. ElectricCar → Car → Vehicle. The constructor chain flows upward, the display chain flows downward.
05 Hierarchical + polymorphism — Appliance Hierarchical

Reuse the Appliance hierarchy for this exercise.

Create Appliance with:

  • Fields: String brand; and double price;
  • A constructor, and methods: public void turnOn(), public void turnOff(), public void displayInfo()

Create WashingMachine extends Appliance with:

  • Field: int loadKg;
  • @Override turnOn() — prints "Washing machine is running with [loadKg]kg load."
  • @Override displayInfo()

Create Refrigerator extends Appliance with:

  • Field: double temperature;
  • @Override turnOn() — prints "Refrigerator is cooling to [temperature]°C."
  • @Override displayInfo()

Create TestAppliance. Store both in an Appliance[] array and loop through to call turnOn() and displayInfo().

--- Appliance 1 --- Washing machine is running with 8kg load. Brand: Samsung, Price: 18999.0, Load: 8kg --- Appliance 2 --- Refrigerator is cooling to 4.0°C. Brand: LG, Price: 32500.0, Temp: 4.0°C
Key learning: The array type is Appliance[] but it holds WashingMachine and Refrigerator objects. When you call turnOn(), Java runs the child's overridden version — this is polymorphism. One method call, different behavior depending on the actual object.

Create Food with:

  • Fields: String name; and int calories;
  • A constructor, and public void displayInfo()

Create Fruit extends Food with:

  • Field: String season;
  • @Override displayInfo()

Create Vegetable extends Food with:

  • Field: boolean isLeafy;
  • @Override displayInfo()

Create TestFood. Store a mix of Food, Fruit, and Vegetable objects in a Food[] array. Loop through and use instanceof to identify the type of each item.

--- Checking food items --- Rice (200 cal) → is Food: true, is Fruit: false, is Vegetable: false Mango (60 cal, Season: Summer) → is Food: true, is Fruit: true, is Vegetable: false Broccoli (55 cal, Leafy: true) → is Food: true, is Fruit: false, is Vegetable: true
Key learning: instanceof checks the actual runtime type. A Fruit instanceof Food is true because Fruit IS-A Food. But a Food instanceof Fruit is false if it was created as a plain Food.

10 Putting it all together — School system Mixed

This exercise combines inheritance, overriding, super, polymorphism, instanceof, and static fields.

Create SchoolMember with:

  • static int totalMembers = 0;
  • Fields: int id; (auto-assigned), String name;, int age;
  • A constructor that auto-increments totalMembers and assigns id.
  • Methods: public String getRole() (returns "Member"), public double getMonthlyPay() (returns 0.0), public void displayInfo()

Create Teacher extends SchoolMember with:

  • Fields: String subject; and double salary;
  • @Override getRole() — returns "Teacher"
  • @Override getMonthlyPay() — returns salary
  • @Override displayInfo() — call super.displayInfo(), then print subject and salary

Create SchoolStudent extends SchoolMember with:

  • Fields: String course;, double gpa;, double tuition;
  • @Override getRole() — returns "Student"
  • @Override getMonthlyPay() — returns 0.0 (students don't get paid)
  • @Override displayInfo() — call super.displayInfo(), then print course, gpa, and tuition
  • A method: public String getStanding()

Create TestSchoolSystem. Create 2 Teachers and 3 Students. Store all 5 in a SchoolMember[] array. Loop through and:

  1. Call displayInfo() on each (polymorphic).
  2. Use instanceof to count teachers vs students.
  3. Compute total monthly payroll (sum of getMonthlyPay()).
  4. Compute total tuition revenue (sum tuition of SchoolStudents using instanceof + casting).
