What is encapsulation?
Encapsulation means bundling data (fields) and the methods that operate on that data into a single class, while hiding the internal state from outside access. In practice:

1. Make all fields private.
2. Provide public getter methods to read values.
3. Provide public setter methods to write values (with validation if needed).
4. The outside world interacts with your object only through these methods — never touching the fields directly.

01 Basic getters and setters — Person Getters Setters

Create a class named Person.

Declare the following private fields:

  • private String name;
  • private int age;
  • private String email;

For each field, create a public getter and a public setter:

  • getName(), setName(String name)
  • getAge(), setAge(int age)
  • getEmail(), setEmail(String email)

Create TestPerson with a main method. Create a Person object, use the setters to assign values, then use the getters to print them.

Name: Maria Santos Age: 25 Email: maria.santos@email.com
Key learning: The fields are private — you cannot write person.name = "Maria" from the test class. You must use person.setName("Maria Santos") instead. This is encapsulation in action.
02 Setter with validation — BankAccount Setters Validation

05 Computed getter — Temperature converter Getters

Create a class named Temperature.

Declare:

  • private double celsius;

Create:

  • getCelsius() and setCelsius(double celsius)
  • public double getFahrenheit() — a computed getter that returns celsius * 9 / 5 + 32 (does not store Fahrenheit as a field)
  • public double getKelvin() — a computed getter that returns celsius + 273.15

Create TestTemperature. Set Celsius to different values and print all three conversions.

Celsius: 0.0 Fahrenheit: 32.0 Kelvin: 273.15 Celsius: 100.0 Fahrenheit: 212.0 Kelvin: 373.15 Celsius: 37.0 Fahrenheit: 98.6 Kelvin: 310.15
Key learning: Not every getter has to map to a stored field. getFahrenheit() and getKelvin() are computed getters — they calculate a value from existing data. This keeps the internal representation clean (only one field) while providing multiple views.
06 Read-only field — ID generator Read-only Constructor

Create a class named ReadOnlyId.

Declare:

  • private static int nextId = 1000; — a static counter shared across all objects
  • private int id; — unique ID, assigned in constructor
  • private String label;

In the constructor, auto-assign id by incrementing nextId. Accept label as a parameter.

Create:

  • public int getId() — getter only, no setter (read-only)
  • public String getLabel() and public void setLabel(String label)

Create TestReadOnlyId. Create 3 objects and print their auto-assigned IDs.

Item: Widget A (ID: 1001) Item: Widget B (ID: 1002) Item: Widget C (ID: 1003)
Key learning: By not providing a setter for id, the field becomes read-only from outside the class. Once assigned in the constructor, it can never be changed. This protects data integrity.

10 Putting it all together — Shopping cart Mixed

Create a class named ShoppingCart. This exercise combines everything: private fields, getters, setters, validation, constructors, computed methods, and arrays.

Declare:

  • private String[] itemNames; — array of item names (max 5 items)
  • private double[] itemPrices; — array of item prices (parallel array)

Create a constructor that accepts customerName and initializes the arrays with size 5 and itemCount to 0.
